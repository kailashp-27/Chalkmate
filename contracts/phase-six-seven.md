# Planning, administration, and pilot readiness

Classroom staff can read private planning records. Only active classroom teachers/owners can create versions, request generation, approve or retry. Students and other workspaces cannot read planning sources, answer keys, notes, jobs or readiness data. Every export is private to staff; student-copy exports omit solutions. No planning action publishes, sends mail or changes marks.

`GET/POST /v1/classrooms/{id}/planning` lists/creates immutable versions. Kinds: syllabus, blueprint, paper, question_bank, meeting, announcement, report_template, report. `POST /v1/planning/{id}/versions` creates a new version with optimistic base-version checking. `POST /v1/planning/{id}/approve` records a separate approval of the latest checked version. `GET /v1/planning/{id}/export?teacher_key=false` exports Markdown. `POST /v1/classrooms/{id}/planning-jobs` queues local Ollama generation from explicitly selected approved source versions; `GET .../planning-jobs` and `POST /v1/planning-jobs/{id}/{cancel|retry}` support recovery. Never silently truncate sources. Store model digest, prompt version, timings and token usage. At most one active planning job and 20 attempts per classroom/day; 3 attempts/job.

Syllabus content uses named topics and source text. Blueprint rows include topic, outcome, question type, difficulty, count and marks per question. Paper/bank questions include topic, wording, marks, solution, rubric and exact source quotes. Paper totals, blueprint allocation, duplicate wording, syllabus coverage and citations are checked before approval. Variants explicitly reference an approved paper and syllabus; equivalence requires later teacher validation. Meeting notes and translations preserve the supplied original alongside the draft. Report templates select allowlisted columns; reports use authoritative recorded classroom activity/approved decisions, not invented data.

`POST /v1/classrooms/{id}/command-preview` only resolves allowlisted navigation intents. It returns a reviewable destination and explanation; it never executes sending, publication or grading. Ambiguous/unsupported text produces no action.

`GET /v1/classrooms/{id}/readiness` reports scoped queue failures/leases and planning usage. Pilot evaluation is an offline validated manifest and metrics report with separate calibration/held-out identities, consent flags, error buckets, review time and latency. An isolated PostgreSQL backup/restore drill verifies a restored copy without modifying the application database. Synthetic checks do not establish real pilot quality targets.

Interface: black/blue and light themes, compact copy, accessible hover/focus/tap help, keyboard command dialog, finite motion and reduced-motion support. Validate private planning/version/approval/export/queue flows, isolation, generated schema errors and command non-execution with integration tests. Verify new-user and mobile browser journeys, keyboard help and reduced motion.
