# Phase 3: reliable review contract

- Preserve every saved rubric. Active assessments may save a reasoned revision against an explicit base version. Teachers inspect a field-level diff before explicitly activating the candidate. New papers use the latest approved rubric; existing papers keep their pinned rubric.
- Re-evaluation is a separate teacher action with a reason and an expected extraction version. It creates a fresh extraction snapshot, cancels pending jobs, changes the paper's pinned rubric, and requires renewed extraction review and grade approval. Previous releases remain student-visible until a replacement is explicitly released. Each release points at an immutable decision and its own rubric.
- Question reviews save append-only criterion marks, feedback, actor, rubric and extraction versions. Stale writes fail. Reviewed question drafts seed final grading; whole-paper approval and separate release remain mandatory.
- A per-assessment queue filters by state, student, question progress, failed jobs, and rubric mismatch. Existing permission scopes apply to queue entries, calibration, and history.
- Calibration snapshots capture teacher reference marks against reviewed answers, a low/middle/high example band, optional current model proposal and deterministic per-criterion deltas/mean absolute error. Samples are rubric/extraction/model-version scoped. Reference-only samples are explicit and excluded from model-comparison averages. No accuracy claims from synthetic samples.
- Feedback cards present teacher-approved question marks and overall feedback. Teachers can inspect version/release history. Student responses expose only the latest released decision, no model answers, internal reasons, references, or unreleased work.
- Extend the rubric builder with accepted alternatives and criterion guidance. All questions remain required; optional-question groups are outside this phase.
- Validate rubric diffs and stale revisions, re-evaluation preservation/replacement, question drafts and stale reads, queue isolation, calibration bounds and privacy, exports, and the complete browser flow. Keep local Ollama and the existing black/blue appearance.
